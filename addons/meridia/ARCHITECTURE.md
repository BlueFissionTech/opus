# Meridia boundaries

The host owns authenticated context, route admission, clock and capability
grants. RouteSource is versioned provenance for one application and nullable
tenant scope, not a remote manifest verifier. RouteCandidate copies a native
Mapping's name and URI; it retains no callback. Native immutable Obj protects
record fields and detached projections. Existing mappings remain host-owned.

RouteService extends DevElation Service. It makes bounded deterministic choices
over the admitted immutable catalog. It owns precedence and alias validation;
it does not own intent classification, HTTP routing or workflow execution.
RouteCommandProcessor decorates Wise and preserves the underlying processor for
unrelated resources and continuations. Both users and governors use fresh host
authority. The generated specialist descriptor requests, but never grants,
meridia.read.

No repository, database, network client, worker, source installation or global
router mutation is introduced. There is no raw SQL. Future storage belongs
behind BlueCore queries/repositories and native Scaffold; future orchestration
belongs to Synematic/Automata and verified Annex capability admission. Resolution
does not substitute for those contracts or confer invocation authority.

The first tests cover actual mappings, application delegation, Wise parsing and
execution, context spoofing, ambiguity, precedence, loop/missing/cross-scope
targets, expiry, revoked access, snapshot isolation, observer failure/reentry and
the disabled crawl policy. Live activation, rollback and deployment remain open.
